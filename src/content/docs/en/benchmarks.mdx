## Setup

- **Remnawave 3.4.5** (`remnawave/backend:3.4.5`) versus **GoWave** at commit [`260548c`](https://github.com/aaaSaZaN/gowave/commit/260548c).
- Run on [GitHub Actions](https://github.com/aaaSaZaN/gowave-bench/actions/runs/39228132732) on a runner with 4 vCPU (AMD EPYC 9V45) and 16 GB RAM. Logs, raw results and the [workflow](https://github.com/aaaSaZaN/gowave-bench/blob/main/.github/workflows/benchmark.yml) are public, so the run can be repeated.
- Docker, each panel limited to **2 CPU and 2 GiB**, each with its own **PostgreSQL 17 on 1 CPU** and identical settings. Remnawave also gets Valkey (0.5 CPU), which it requires.
- The same data, created through each panel's API: 1,000 users, 20 hosts, a profile and a squad.
- Load is generated by [k6](https://k6.io) 1.6.1: each iteration is one HTTP request. Responses are validated: an error, an empty subscription or HTML counts as a failure.
- Run order alternates and is shuffled; every run has a warmup. Each run lasts 20 seconds, three repetitions, tables show the median.
- Before every run both panels' databases get `CHECKPOINT` and `VACUUM ANALYZE`, so one run does not slow down the next.
- Latency is server response time (k6 `timings.duration`); p99 is the median across runs.

## Memory and startup

- **Memory** (median across all runs, whole panel container including workers): GoWave about 59 MiB, Remnawave about 1,082 MiB.
- **Startup** until the first authenticated API response (median of 10 trials): GoWave 149 ms, Remnawave 4.3 s.

## Worth knowing

- **Dashboard stats at 32 clients and more (up to 6.3×)** comes from coalescing concurrent requests: while one computation runs in the database, the others wait for its result. Such a stampede on one endpoint is rare; the everyday difference shows with a single client: **2.5×**.
- **Writes from 32 clients up are limited by GoWave's PostgreSQL**, not by the application: the database, capped at 1 CPU, is throttled in 18-23% of periods, the panel container is not.
- **Nodes are not part of the test.** Node management, traffic collection, HWID and real VPN clients were not measured, only the panel API.
- **This is a shared GitHub Actions virtual machine**, not a capacity study: the active panel, its database and k6 share 4 cores, and runs are short. The numbers show the ratio, not absolute limits.

## Where the numbers come from

The tests live in the public [gowave-bench](https://github.com/aaaSaZaN/gowave-bench) repository: k6 scenarios, both panels in Docker, data preparation and charts. Runs happen on [GitHub Actions](https://github.com/aaaSaZaN/gowave-bench/actions/workflows/benchmark.yml): the workflow builds GoWave from source, pulls the Remnawave image and compares them on the same virtual machine.

Every run's logs, machine details and raw results (in the artifacts) are public. The numbers on this page come from [run 39228132732](https://github.com/aaaSaZaN/gowave-bench/actions/runs/39228132732). To check them, fork the repository and run the **Benchmark** workflow with the `full` profile.
