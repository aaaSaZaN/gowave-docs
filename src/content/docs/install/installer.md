Нужны сервер на Debian/Ubuntu или RHEL-семействе (`amd64` или `arm64`) и домен, A-запись которого указывает на IP сервера. Панель открывается только по домену через HTTPS, поэтому без домена установщик не продолжит. Если прокси свой, домен может указывать и не на этот сервер.

```bash
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/aaaSaZaN/gowave/main/install.sh)"
```

Запускайте в SSH-сессии: установщик задаёт вопросы и без интерактивного терминала не стартует. Исключение - обновление с флагом [`--update`](#параметры-командной-строки). Ещё он проверяет, что запущен от root, что в системе есть systemd и `apt` или `dnf`, и доставляет недостающие `curl`, `tar`, `openssl`, `ss` и `sha256sum`.

## Что спросит установщик

1. **Язык** вопросов и сообщений: русский или английский.
2. **Перенос.** Если на сервере найдена Remnawave или PasarGuard, установщик предложит перенести её данные, см. [ниже](#переезд-с-другой-панели).
3. **База данных.** SQLite - один файл, без Docker, обновление прямо из панели. Или PostgreSQL в Docker. При переносе база выбирается в предыдущем пункте.
4. **Канал обновлений.** Stable - проверенные релизы, Dev - сборка каждого коммита в `main`, см. [Обновление](../updating/#каналы-stable-и-dev).
5. **Reverse proxy.** Caddy (сертификат выпускается и продлевается сам), Nginx с Certbot или свой прокси, см. [ниже](#свой-reverse-proxy).
6. **Домен панели.** Для Caddy и Nginx установщик проверит, что домен резолвится, и сверит его A и AAAA-записи с внешним IP сервера. Если IP другой, например домен за прокси Cloudflare, он спросит, продолжать ли: сертификат в таком случае может не выпуститься.
7. **Путь панели**, по умолчанию `/`, см. [ниже](#путь-панели).
8. **Локальная нода.** Поставить ли GoWave Node на этот же сервер, когда панель заработает, см. [ниже](#локальная-нода).

Затем установщик смотрит, кто держит порты 80 и 443. Занять их может только выбранный прокси, уже работающий на этом сервере, или прежняя панель, которую он остановит. Для самой панели он возьмёт первый свободный порт начиная с 3000.

Перед установкой появится сводка: адрес панели, её локальный порт, база, канал, прокси и что будет с прежней панелью. Пока вы её не подтвердите, установщик ничего не ставит, кроме недостающих утилит.

## Что он сделает

1. Скачает бинарник, веб-интерфейс и `SHA256SUMS` и сверит контрольные суммы. При несовпадении установка прерывается.
2. Запишет `/opt/gowave/.env`: сгенерирует `APP_SECRET`, пропишет домен, путь панели и порты. Порт метрик Prometheus - первый свободный начиная с 3001, сами метрики выключены (`METRICS_ENABLED=false`), как их включить, написано в файле.
3. Если выбран перенос, скопирует данные прежней панели и её настройки уведомлений, затем остановит её.
4. Создаст службу `gowave`, которая работает от системного пользователя `gowave` с ограничениями systemd, и команду `/usr/local/bin/gowave`. Подробнее о службе - на странице [Systemd и SQLite](../systemd/#ограничения-службы).
5. Запустит панель и дождётся ответа `/api/system/health`.
6. Для PostgreSQL поставит Docker с `get.docker.com`, если его нет, и переведёт панель в `/opt/gowave-docker` командой [`gowave migrate to-docker`](../../migration/sqlite-to-docker/). Поэтому панель с PostgreSQL сначала стартует на SQLite. Данные Remnawave при этом копируются сразу в PostgreSQL, без промежуточного SQLite.
7. Настроит прокси с HTTPS, откроет порты 80 и 443 в `ufw` или `firewalld` и проверит, что панель отвечает по `https://<домен>`.
8. Если вы согласились, поставит локальную ноду.

Панель слушает только `127.0.0.1` и доступна по `https://<домен><путь панели>`.

:::caution[Сразу откройте панель]
Первый, кто откроет панель, создаёт администратора. Зайдите в неё сразу после установки. После переноса с Remnawave входите под прежним администратором.
:::

### Caddy

Caddy ставится из официального репозитория (Cloudsmith для Debian/Ubuntu, COPR для RHEL). Сайт панели пишется в `/etc/caddy/gowave.caddy`. Стандартный `Caddyfile` из пакета установщик заменяет строкой `import`, а в ваш собственный `Caddyfile` эту строку дописывает. Если Caddy не примет итоговую конфигурацию (например, домен уже описан у вас), исходный `Caddyfile` вернётся на место.

### Nginx

Ставятся `nginx` и `certbot`, на RHEL - из EPEL. Сначала поднимается сайт только на порту 80, и Certbot выпускает сертификат через webroot `/var/www/gowave-acme`. Затем пишется полный `/etc/nginx/conf.d/gowave.conf`:

- редирект с HTTP на HTTPS, TLS 1.2 и 1.3, HTTP/2;
- WebSocket для SSH-терминала нод с таймаутом в час;
- сжатие ответов и запросы до 50 МБ, этого хватает для загрузки бэкапа;
- блок, который обрывает TLS-рукопожатие для любых других имён, чтобы сканер по IP не видел сертификат панели. Он добавляется, если Nginx версии 1.19.4 или новее и у вас нет своего `default_server` на 443.

Хук `/etc/letsencrypt/renewal-hooks/deploy/gowave-nginx.sh` перезагружает Nginx после продления сертификата. Если домен уже описан в другом файле `/etc/nginx`, установщик остановится и попросит убрать этот `server`. На системах с SELinux он включает `httpd_can_network_connect`, иначе Nginx не достучится до панели.

## Если установка прервалась

Если ошибка случилась до первого запуска панели, установщик убирает всё созданное им: службу, бинарник, веб-интерфейс, `.env`, базу и команду `gowave`. Остальное содержимое `/opt/gowave` он не трогает. Прежняя панель, если её успели остановить, запускается обратно с той же политикой перезапуска. Повторный запуск установщика начнёт установку с нуля.

После первого запуска панели установщик уже ничего не откатывает. Если не удался переход в Docker, панель продолжит работать на SQLite. Если порты 80 и 443 к этому моменту кто-то занял, освободите их и запустите установщик снова, пункт «Настроить домен и HTTPS». Неудачная установка ноды панель не трогает, её можно повторить из меню.

## Файлы

| Путь | Что там |
| :--- | :--- |
| `/opt/gowave` | Бинарник, веб-интерфейс, `.env` и база `gowave.db` |
| `/opt/gowave-docker` | `docker-compose.yml` и `.env`, если выбран PostgreSQL |
| `/etc/systemd/system/gowave.service` | Служба панели |
| `/etc/systemd/system/gowave.service.d/90-unprivileged.conf` | Пользователь и ограничения службы |
| `/etc/systemd/system/gowave-update.path`, `gowave-update.service` | Обновление из панели от root |
| `/usr/local/bin/gowave` | Ссылка на бинарник для CLI |
| `/etc/caddy/gowave.caddy` | Сайт для Caddy |
| `/etc/nginx/conf.d/gowave.conf` | Сайт для Nginx |
| `/var/log/gowave-install.log` | Полный лог установщика |

## Свой reverse proxy

Пункт «Не настраивать: свой reverse proxy» нужен, если на сервере уже работает свой прокси (Angie, Traefik, HAProxy, Caddy или Nginx в Docker), прокси стоит на другом сервере или панель открывается через Cloudflare Tunnel. Установщик поставит только панель и не тронет порты 80 и 443, прокси и файрвол. Проверки DNS тоже не будет. Выбор запоминается в `.env` как `GOWAVE_PROXY=external`.

В конце он покажет адрес, на который нужно направить прокси, обычно `http://127.0.0.1:3000`. Прокси должен передавать путь без изменений и заголовки `Host`, `X-Forwarded-For` и `X-Forwarded-Proto`, а для SSH-терминала нод ещё WebSocket (`Upgrade` и `Connection`). Готовые настройки есть для [Caddy](../reverse-proxy/caddy/) и [Nginx](../reverse-proxy/nginx/).

:::note[Прокси в Docker]
Панель слушает только `127.0.0.1` сервера, и контейнер с прокси в обычной сети Docker её не увидит. Запустите прокси с `network_mode: host`.
:::

Пока прокси не настроен, панель открывается только с самого сервера, поэтому создать администратора извне никто не сможет. Перейти на Caddy или Nginx позже можно через пункт меню «Настроить домен и HTTPS».

## Путь панели

Веб-интерфейс можно открыть не в корне домена, а по своему пути, например `https://panel.example.com/private/panel/`. Установщик спрашивает путь при установке и записывает его в `PANEL_BASE_PATH`. Подойдут `panel`, `/panel` и `/panel/` - это одно и то же. В пути допустимы латиница, цифры, `_` и `-`, вложенные пути тоже работают, а `/api` и `/metrics` заняты.

Путь меняет только адрес интерфейса. API, подписки, WebSocket и метрики остаются на своих местах, поэтому путь не закрывает доступ к API. При своём пути корень `/` отвечает 404.

Пункт меню «Изменить путь панели» сохраняет копию `.env`, перезапускает панель и проверяет, что интерфейс открывается по новому адресу. Если проверка не прошла, прежний `.env` возвращается. Обычные обновления и [переход в Docker](../../migration/sqlite-to-docker/) путь сохраняют.

## Локальная нода

Установщик может поставить [GoWave Node](../node/install/) на тот же сервер: после установки панели (вопрос в конце) или пунктом меню «Установить или обновить локальную ноду». Он берёт `SECRET_KEY` у панели сам и запускает [установщик ноды](../node/install/).

- Для новой ноды он спросит порт, по умолчанию `2222`. У уже установленной ноды порт и ключ сохраняются.
- Ноду в панели установщик не регистрирует и профиль не создаёт. Добавьте ноду сами с адресом и портом, которые он покажет: на systemd это `127.0.0.1`, в Docker - внешний IP сервера, ведь контейнер панели не видит loopback хоста.
- Неудачная установка ноды не останавливает панель. Удаление панели ноду не удаляет.

## Переезд с другой панели

Если на сервере найдена **Remnawave** (`/opt/remnawave`) или **PasarGuard** (`/opt/pasarguard`, SQLite или PostgreSQL/TimescaleDB), установщик предложит перенести данные в GoWave - на SQLite или на PostgreSQL в Docker. PasarGuard на MySQL и MariaDB не переносится. Импорт из [3x-ui](../../migration/3x-ui/) установщик не делает, он запускается командой.

На время копирования установщик гасит только контейнер приложения прежней панели, её база продолжает работать. После переноса прежняя панель останавливается целиком и пропадает из автозагрузки, но её контейнеры и данные остаются на месте. Если перенос не удался, установщик запустит её обратно. Подробнее - в разделе [Миграция](../../migration/remnawave/).

## Повторный запуск

Та же команда на сервере, где GoWave уже стоит, открывает меню:

- «Обновить GoWave». Сначала спросит канал, Enter оставляет текущий. На systemd установщик скачивает и проверяет новый релиз, заново применяет ограничения службы, перезапускает панель и ждёт её ответа. В Docker он прописывает образ канала в `GOWAVE_IMAGE` и выполняет `docker compose pull` и `up`. Свой образ (локальная сборка, зеркало) установщик не меняет. В старых `docker-compose.yml` он заодно привязывает порт панели к `127.0.0.1`. Если домен с HTTPS так и не настроен, предложит настроить его.
- «Настроить домен и HTTPS». Можно сменить домен или перейти между Caddy, Nginx и своим прокси. Настройки прежнего прокси для панели удаляются, `PANEL_DOMAIN` и `SUB_PUBLIC_DOMAIN` в `.env` обновляются, панель перезапускается.
- «Изменить путь панели», см. [выше](#путь-панели).
- «Установить или обновить локальную ноду», см. [выше](#локальная-нода).
- «Перенести уведомления Telegram и вебхуки из старой панели». Копирует их из `/opt/remnawave/.env` в `.env` GoWave и перезапускает панель. Значения `change_me` пропускаются. Telegram включается, только если есть токен бота, а вебхуки - только с подходящим `WEBHOOK_SECRET_HEADER`.
- «Удалить GoWave». Нужно ввести `yes`. По желанию установщик сначала сохранит `.env` и базу в `/root/gowave-backup-<дата>`, для PostgreSQL через `pg_dump`. Затем удалит панель, её базу, том PostgreSQL, службы, команду `gowave` и сайт в Caddy или Nginx. Пакеты Caddy и Nginx, Docker, сертификаты и локальная нода остаются. Если Caddy ставился только для GoWave, он отключается.

## Параметры командной строки

Параметры передаются после `_` или как переменные окружения, например для Ansible:

```bash
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/aaaSaZaN/gowave/main/install.sh)" _ --dev
```

| Параметр | Переменная | Что делает |
| :--- | :--- | :--- |
| `--stable`, `--dev`, `--channel stable\|dev` | `GOWAVE_CHANNEL` | Канал обновлений без вопроса |
| `--version v1.2.3` | `GOWAVE_VERSION` | Закрепить stable-релиз. `dev` выбирает канал dev |
| `--update` | `GOWAVE_ACTION=update` | Обновить существующую установку без вопросов и без терминала |
| `--lang ru\|en` | `GOWAVE_LANG` | Язык сообщений без вопроса |

`--update` оставляет установленный канал, если другой не указан, поэтому подходит для cron и Ansible:

```bash
curl -fsSL -o /tmp/gowave-install.sh https://raw.githubusercontent.com/aaaSaZaN/gowave/main/install.sh
sudo bash /tmp/gowave-install.sh --update --lang ru
```

Новая установка всё равно требует терминала: ей нужны ответы про домен, прокси и базу. Готовые плейбуки лежат в [gowave-ansible](https://github.com/aaaSaZaN/gowave-ansible).

Если установщик вам не годится, панель ставится вручную:
