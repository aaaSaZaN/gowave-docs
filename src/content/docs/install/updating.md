Панель сама проверяет релизы на GitHub и показывает в шапке, что вышла новая версия. Нажмите на версию, откроется окно **Build Info**: там видно, когда была последняя проверка, а кнопка **Check now** спрашивает GitHub заново, не дожидаясь кеша.

## Каналы stable и dev

| | Stable | Dev |
| :--- | :--- | :--- |
| Откуда | Теги `v*` | Каждый коммит в `main`, прошедший CI |
| Бинарники | [Последний релиз](https://github.com/aaaSaZaN/gowave/releases/latest) | Пре-релиз [`dev`](https://github.com/aaaSaZaN/gowave/releases/tag/dev), он пересобирается на каждый коммит |
| Docker | `ghcr.io/aaasazan/gowave:latest`, `:1.2.3` | `ghcr.io/aaasazan/gowave:dev`, `:dev-<sha>` |
| Версия | `v1.2.3` | `dev-<sha>` |

Dev-сборки могут быть нестабильными, зато исправления в них появляются сразу. Панель на dev показывает версию красным. Stable-обновления и тег `latest` dev-сборки никогда не подхватывают. Pre-release с тегами вида `v1.2.0-beta.1` тоже не предлагаются, их ставят вручную через [`--version`](../installer/#параметры-командной-строки).

Канал выбирается в **Build Info** переключателем **Stable (releases)** / **Dev (every commit)**, а также в установщике. Дальнейшие обновления остаются на выбранном канале.

:::caution[Сначала резервная копия]
Stable-релиз может оказаться старше dev-сборки, с которой вы уходите. Изменения базы, которые сделала dev-сборка, при этом не откатываются. Перед переключением канала сделайте копию базы.
:::

## Systemd и SQLite

Нажмите **Update panel** (или **Switch to dev** / **Switch to stable** при смене канала) в окне **Build Info**. Сама панель работает без прав root и свои файлы заменить не может, поэтому она только оставляет запрос в `/run/gowave`. Его выполняет отдельная служба `gowave-update` от root:

1. скачивает бинарник, веб-интерфейс и `SHA256SUMS` выбранного канала;
2. сверяет контрольные суммы;
3. ставит веб-интерфейс, заменяет бинарник, а прежний оставляет рядом как `gowave-server.bak`;
4. заново применяет ограничения службы и перезапускает панель.

Окно показывает каждый шаг, процент загрузки и журнал. Если обновление сорвалось, там же будет ошибка, а панель продолжит работать на прежней версии. Обычно всё занимает до минуты. Подробный журнал на сервере:

```bash
journalctl -u gowave-update.service
```

Если новая версия всё-таки не устраивает, вернуть прежний бинарник можно вручную:

```bash
cp /opt/gowave/gowave-server.bak /opt/gowave/gowave-server && systemctl restart gowave
```

На установках, сделанных до появления службы обновления, вместо кнопки панель покажет команду установщика. После одного обновления через установщик кнопка заработает.

Или повторно запустите установщик - он откроет меню с пунктом обновления и спросит канал. Установщик при этом заново применяет ограничения службы:

```bash
sudo bash -c "$(curl -fsSL https://raw.githubusercontent.com/aaaSaZaN/gowave/main/install.sh)"
```

Для обновления без вопросов, например из cron или Ansible, есть флаг [`--update`](../installer/#параметры-командной-строки).

## Docker

В Docker кнопки нет - панель показывает команду, которую нужно выполнить на сервере:

```bash
cd /opt/gowave-docker && docker compose pull && docker compose up -d
```

Канал в Docker задаёт образ в `GOWAVE_IMAGE` из `.env`. При смене канала в **Build Info** панель покажет команду, которая его заменит:

```bash
cd /opt/gowave-docker
sed -i '/^GOWAVE_IMAGE=/d' .env && echo 'GOWAVE_IMAGE=ghcr.io/aaasazan/gowave:dev' >> .env
docker compose pull && docker compose up -d
```

Чтобы вернуться на stable, укажите `:latest` вместо `:dev`. Путь к проекту в подсказке берётся из `GOWAVE_COMPOSE_DIR`.

Контейнер не может заменить собственный образ. Обновлять его должен кто-то снаружи, а для этого нужен доступ к Docker-сокету, то есть права root на хосте. Давать такой доступ веб-панели небезопасно: взлом панели превратился бы во взлом сервера. Поэтому обновление в Docker остаётся обычной командой.

## Версия

```bash
gowave --version
```

В Docker: `docker exec gowave /app/gowave --version`.
