## Команды

| Команда | Что делает |
| :--- | :--- |
| `gowave-node status` | Состояние службы, демона и ядра Xray |
| `gowave-node status --wait-running` | Дождаться старта управляющего демона ноды (до 30 с) |
| `gowave-node status --wait-ready` | Дождаться, пока нода получит конфигурацию и Xray запустится (до 120 с) |
| `gowave-node logs -n 100 -f` | Журнал службы ноды |
| `gowave-node xlogs -n 100 -f` | Журнал ядра Xray (или отдельная команда `xlogs`) |
| `gowave-node restart` | Перезапуск службы |
| `gowave-node update` | Интерактивный выбор и обновление версии ноды |
| `gowave-node update -y` | Обновить ноду до последнего стабильного релиза |
| `gowave-node update --version v1.1.5 -y` | Поставить конкретную версию ноды |
| `gowave-node core install` | Интерактивный выбор и установка ядра Xray |
| `gowave-node core install -y` | Поставить последнюю стабильную версию Xray |
| `gowave-node core install --version v26.7.28 -y` | Поставить конкретную версию Xray |
| `gowave-node core install --repo owner/repo --version v1.0.0 -y` | Поставить кастомное ядро Xray из стороннего репозитория |
| `gowave-node core update` | Обновить ядро Xray до последнего стабильного релиза |
| `gowave-node core reset` | Вернуть стандартное управляемое ядро `rw-core` |
| `gowave-node version` | Вывести текущую версию ноды |

Запускайте команды от root (или через `sudo`): CLI взаимодействует с демоном через служебный файл обнаружения в каталоге `/run/gowave-node` (или по пути из переменной `GOWAVE_NODE_RUNTIME_DIR`). На установках, переехавших со старого имени, работают и прежние команды `remnanode` и `remnanode-go`.

Установщик также создаёт системный симлинк `xlogs`, поэтому журнал ядра доступен напрямую: `xlogs -n 100 -f`.

## Статус и журналы

- `gowave-node status` проверяет доступность управляющего сокета ноды, состояние юнита в systemd (или другой init-системы), путь и версию найденного ядра Xray, а также версию самой ноды.
- В `gowave-node logs` (алиас: `gowave-node nodelogs`) и `gowave-node xlogs` флаг `-n` (или `--lines`) задаёт количество выводимых строк (по умолчанию 100), а `-f` (`--follow`) оставляет поток логов открытым. Журнал ноды читается прямо из кольцевого буфера в оперативной памяти.

## Обновление ноды

Команда `gowave-node update` без параметров выводит список последних релизов на GitHub и запрашивает подтверждение номера версии:

```bash
gowave-node update
```

Флаги команды:

- `-y`, `--yes` - применить обновление без лишних вопросов;
- `--channel <release|prerelease>` - выбор канала обновлений (по умолчанию `release`);
- `--version <тег>`, `-v <тег>` - установка конкретной версии;
- `--repo <владелец/репозиторий>`, `-r <владелец/репозиторий>` - репозиторий на GitHub (по умолчанию `aaaSaZaN/gowave-node`).

Обновление выполняется транзакционно: сохраняется резервная копия предыдущего бинарника (`.previous`), новый файл валидируется перед заменой, а при сбое старта нода автоматически откатывается на прежнюю версию.

## Управление ядром Xray

Команда `core` управляет исполняемым файлом Xray и базами геоданных:

- `gowave-node core install` проверяет релизы `XTLS/Xray-core`, валидирует бинарник и обновляет файлы `geosite.dat` и `geoip.dat` в каталоге ассетов.
- Флаги `--version <тег>` и `--repo <репозиторий>` позволяют выбрать конкретный релиз или альтернативный форк ядра.
- `gowave-node core reset` удаляет кастомные настройки и возвращает стандартный бинарник `rw-core`.

### Установка кастомного ядра

Для установки кастомного ядра из стороннего GitHub-репозитория укажите владельца, имя репозитория и тег:

```bash
gowave-node core install --repo <владелец/репозиторий> --version <тег> -y
```

Примеры:

```bash
# Установка стабильного релиза из официального репозитория
gowave-node core install --repo XTLS/Xray-core --version v26.7.28 -y

# Установка форка ядра из стороннего репозитория
gowave-node core install --repo owner/custom-xray --version v1.0.0 -y
```

Что нужно для успешной установки:

- В релизах указанного репозитория на GitHub должны быть архивы (`.zip`) или бинарники под архитектуру сервера (например, `Xray-linux-64.zip` или архив под `arm64`).
- Бинарник должен поддерживать стандартные флаги запуска Xray. Перед подменой нода проводит тестовый запуск с рабочей конфигурацией и активирует ядро только после успешной проверки.

### Что происходит при обновлении ноды

Команда `gowave-node update` обновляет исключительно бинарник самой ноды Gowave Node.

Установленное ядро Xray при этом не перезаписывается и не сбрасывается. Если вы поставили сторонний форк через `core install` или указали ядро по прямой ссылке, нода продолжит работать с ним и после собственного обновления. Вернуть стандартное официальное ядро Xray можно в любой момент командой `gowave-node core reset`.

## Обновление из панели

В веб-интерфейсе Gowave:

- **Xray Core**: в карточке ноды нажмите на версию ядра. Откроется окно с выбором стабильного релиза, pre-release или полем для прямой HTTPS-ссылки на архив либо бинарник ядра.
  Пример прямой ссылки:
  `https://github.com/XTLS/Xray-core/releases/download/v26.7.28/Xray-linux-64.zip`
  или прямая ссылка на raw-бинарник вашего форка:
  `https://example.com/builds/xray-linux-64`
- **Gowave Node**: версия самой ноды переключается в селекторе версий Gowave Node. Список релизов загружается из репозитория [gowave-node](https://github.com/aaaSaZaN/gowave-node). Панель отправляет команду ноде, а та выполняет безопасное обновление с автоматической проверкой готовности.

Обновление из панели требует systemd. На Entware обновляйте ноду через консоль командой `gowave-node update`. На хосте только с s6 обновление из панели работает при внешнем супервизоре перезапуска, без него нода отклонит запрос и оставит прежний бинарник.
